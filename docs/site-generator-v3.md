# Suite Artisan - Site Generator V3

## Purpose

V3 is a compositional engine, not a template catalogue. A persisted grammar
combines twenty-one validated axes. A direction constrains compatible choices
but never maps to a single HTML file. The renderer changes page order, hero
DOM, proportions, typography, services, project presentation, motion and the
mobile composition.

## Architecture

- `generator/v3/grammar.py`: registries, direction constraints and 12 page silhouettes.
- `generator/v3/selector.py`: deterministic choice, weighted similarity and anti-clone search.
- `generator/v3/context.py`: strict version gate plus escaped real-data context.
- `generator/v3/sections.py`: structural hero, gallery, service and content systems.
- `generator/v3/styles.py`: base layout, direction tokens, motion and mobile personalities.
- `generator/v3/renderer.py`: semantic static document, SEO, form and composition.
- `generator/v3/media/`: contextual queries and provider-independent assets.

`generator/site_generator.py` is the only runtime entry point and V3 is the
only active Site Vitrine engine. It accepts a valid `v3.x` grammar or fails
with a controlled error. There is no V3-to-V2 fallback and no legacy renderer.

## Design grammar

The persisted axes are direction, silhouette, header, hero, typography, grid,
spacing, surface, photo strategy, image treatment, project showcase, services
composition, content density, transitions, CTA, motion, spatial level,
decoration, footer, mobile personality and ambience. Every value is validated
against the backend registry before persistence or adoption.

The six Gold Standards are represented by constraints:

- editorial luxury for painters;
- premium conversion for plumbers;
- technical spatial for electricians;
- architectural brutalist for masons;
- warm craft for joiners;
- cinematic luxury for renovators.

Two additional directions, minimal architecture and material editorial, widen
the search space. Trade compatibility is weighted, not hardcoded into six
templates.

## Data honesty and missing data

Sections are conditional on real data. No review, statistic, insurance,
certification, service area or phone claim is synthesized. Zero photos use a
direction-specific graphic composition. One photo becomes a dominant project,
two a diptych, three an editorial trio, and larger sets a sequenced gallery.
Services accept any count, including zero.

New sites start with no inferred tagline or service list. When persisted
content exactly equals one of the known bundles formerly generated by V2 or
legacy, V3 omits it and reports an Admin warning. The database is not
rewritten. Any genuinely customized content remains untouched.

## V2 to V3 migration

Existing V2 profiles remain readable historical data and published HTML is
never regenerated by a deployment. They cannot be rendered. The next Admin
generation creates a separate V3 candidate; preview, adoption and publication
remain separate explicit actions. Abandoning the candidate preserves the V2
profile and delivery. Adopting promotes the V3 profile but never publishes it.

New sites require no engine preference: their first generation, preview and
alternative all use V3. Historical `design_preferences.engine_version` and
`preferred_family` keys may remain in old database rows for compatibility, but
are deprecated, ignored by selection, and absent from the Admin/API write
schemas. No database migration is required for this JSON-only compatibility.

Candidate previews reuse the secure preview session and `/admin/preview-api`.
The quote form in preview cannot create a real lead. Public V3 HTML keeps the
existing `/pub/{slug}/demande-devis` contract.

## Motion, spatial and performance

Motion levels range from none to spatial. All movement is progressive and
disabled by `prefers-reduced-motion`. The technical direction uses an inline
SVG/CSS spatial plan by default, avoiding a large WebGL dependency and keeping
the fallback available on modest devices.

Images are processed to WebP before use, include intrinsic dimensions when
known, use eager/high priority only in the hero and lazy decoding elsewhere.
The output is autonomous HTML/CSS/vanilla JS with no runtime design library.

## Testing

The acceptance fixture contains three sites for each of six trades. Within a
trade the silhouette, hero and image treatment are distinct, with a distinct
typography/services pair. Tests cover zero-data honesty, arbitrary service
counts, cross-trade signatures, deterministic selection, strict rejection of
V2/legacy input, controlled V3 failures and provider failures.

Visual artifacts are generated outside Git. Desktop, 390px mobile, grayscale
and silhouette contact sheets are review aids; automated signatures alone do
not establish premium quality.
